# 家用软路由界面与管理改进 v0.1

记录日期：2026-11-20。基线：已交付 OpenWrt 25.12.6 / home 0.1.0-rc1，J4125、8GB 内存、120GB SSD。本文件将用户提出的 eSir 使用体验整理为改进要求，并记录实查结果；不代表已经安装主题、变更界面或重建固件。

## 一、Argon 主题

用户指定：https://github.com/jerrykuku/luci-theme-argon 。核查时官方最新 release 为 v3.1.4，发布于 2026-11-13；项目已提供 APK v3 格式及集成主题配置。构建/打包前仍需重新锁定发布包和 SHA256，不跟随 master 自动更新。

目标：中文界面、清晰侧边栏、浅色/深色模式、桌面与手机布局。保留现有 Bootstrap 作为可切换的备用主题。主题更新由用户手动发起，纳入现有稳定性与回退流程。

新 Argon 已集成配置功能，不重复安装旧的 luci-app-argon-config。主题配置与路由网络参数分开管理，切换主题不自动修改 LAN/WAN、防火墙或 DNS。

验证：登录/退出、系统概览、接口编辑、Dockerman JS、PassWall2、ZeroTier、软件包上传、打印及手机布局；确认可切换回 Bootstrap。官方宣称的广泛兼容不等于本项目组合已经测试通过。

## 二、Docker 管理

用户参考：https://github.com/lisaac/luci-app-dockerman 。该仓库 Makefile 当前声明 v0.5.26，依赖 luci-compat、luci-lib-docker、luci-lib-ip 等。

交付 manifest 已包含 Docker/dockerd 29.6.1、Compose 5.1.4，以及 OpenWrt LuCI 维护版 luci-app-dockerman。交付菜单为“服务 → Dockerman JS”，维护版依赖与用户参考版本不同，不能仅凭同名直接覆盖。

改进要求：容器、镜像、网络、卷、日志、资源占用与常用启停操作入口清楚；采用 lisaac 项目的交互作为参考，同时验证现有 Docker API 与管理前端兼容性。默认先保留当前维护版；若改用 lisaac 原版，需单独验证、打包及提供恢复路径，不能把尚未验证的替换当作交付结论。

容器数据目录延续本地 /srv/data 的存储规划，下载文件仍可放群晖。主题安装不自动迁移 Docker 数据或重启现有容器。

## 三、SMB/CIFS 网络文件夹挂载

交付 manifest 已包含 cifsmount 6.11-r2 和 kmod-fs-cifs；这些提供挂载能力，不等于已经有方便填写共享信息的 SMB 网页配置表单。

改进要求：提供 SMB 客户端挂载页，填写 NAS 地址、共享名、可选子目录、用户名、密码、SMB 协议及本地挂载点；显示连接状态、错误原因，并提供手动挂载、卸载和重试。支持 SMB3，按群晖实际配置验证 3.1.1/3.0；不为兼容默认开启 SMB1。

用户名与密码必须走受限配置/凭据文件，不拼接进 shell，不写入日志、命令行或公共构建仓库；凭据文件权限 0600。具体实现仍需开发和实机验证。

远程共享断开不能阻塞路由启动，下载管理继续使用已有 NAS 保护机制：确认正确挂载源及共享标识后再写入，断开时暂停下载，避免把挂载点下的本地目录误当作群晖。不自动格式化、不自动清空缓存或下载数据。

NFS 继续作为可选挂载方式；BT 下载任务仍由 OpenWrt 上的 Transmission 执行，文件保存在群晖。

## 四、USB 打印

交付 manifest 已包含 luci-app-p910nd、p910nd 0.97-r14、kmod-usb-printer。已有“服务 → p910nd - Printer server”入口，实际中文名称以翻译为准。固件初始未启用打印服务。

改进要求：明确显示 USB 打印设备、在线状态、服务状态、监听端口和启用操作。具体兼容性需要打印机型号及真实接入结果；打印与扫描分开验收，p910nd 不作为扫描支持的承诺。

## 五、常用网络设置更简明

Argon 改善外观，不会自动减少 LuCI 的网络配置复杂度。拟在保留现有高级设置的前提下增加常用入口：

- 上网设置：有线 WAN 的 DHCP/PPPoE/静态 IP、当前地址、网关与连接状态。
- 局域网：LAN 地址、DHCP 开关、地址范围与 DHCP 租约。
- 设备管理：设备名称、IP、MAC、联网状态；连接已有按设备/时间控制功能。
- 备用上网：USB Wi-Fi WAN 的启用、扫描、连接和当前出口；沿用有线主用、Wi-Fi 手动备用。
- 接口概览：物理网卡名称、MAC、链路速率及明确的 WAN/LAN 标记。
- 诊断入口：连通性、DNS、网页测速、群晖访问检查。

物理端口映射必须根据实机确认，不能从 eth0/eth1 编号猜测。更改 LAN 地址、WAN 或 DHCP 等会影响管理连接的操作，应保留 LuCI 的确认与回退流程。高级接口、防火墙及路由页面保持可访问。

## 交付与验收边界

优先将主题与网页入口制作成可独立安装的版本化补丁，验证依赖和恢复方法；需要调整内核/网络基础组件时另做新版固件，不覆盖历史镜像。后续整体构建应同时纳入已完成的 ZeroTier 网页补丁，并使用新的项目版本号。

实际验收需覆盖：新主题下全部已选插件页面、手机操作、网络变更回退、SMB 断开与恢复、打印机实际打印、Docker 容器管理。完成验收前保持“待验证”，不以安装包存在或页面出现代替业务可用。
